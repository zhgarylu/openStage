# OpenStage · 验证版 UI 设计方案

状态：待评审｜2026-11-02｜名称及深色视觉方向已确认；细节待评审

## 1. 版本与设计目标

先做「短剧创作者验证版」：围绕找工具、看上手条件、查看原项目、阅读本周精选的路径，验证内容是否有用。建议首批 50–100 个高相关项目；数量是目标假设，不作为降低质量的门槛。覆盖六步流程，优先充实出图、视频、声音和剪辑。项目示例和数据在设计阶段均为占位，不代表真实结论。

本版包含：首页、流程总览、流程/分类列表、项目详情、周榜及历史期、搜索、关于；共用头部、页脚、移动导航。支持中文搜索、分类与基础筛选、原仓库跳转。内容更新和榜单审核在站外完成，榜单仅展示已审核版本。

暂缓：登录、评论、在线运行、模型下载、相似项目、曲线图、复杂评分、付费功能、独立后台、大规模通用 Skill/MCP 栏目。已实测仅支持少量人工记录；无记录则不展示徽章。

核心体验：三秒看懂用途；一屏找到流程；点击前看到上手门槛；结论有来源；不知道就明确显示未确认。

## 2. 信息架构

- `/` 首页：搜索、精选周榜、六步流程、新收录、编辑推荐、关于入口。
- `/flow/` 流程总览：六步及适合的任务，入口指向对应分类。
- `/flow/[step]/` 流程/分类列表：步骤介绍、筛选、排序、项目列表。六步共享模板；工作流为额外分类入口。
- `/p/[slug]/` 项目详情：用途、上手条件、证据、许可证、风险、原项目链接。
- `/weekly/` 最新已审核周榜及历史入口；`/weekly/[week]/` 为归档详情。
- `/search/?q=...` 中文搜索及结果筛选。
- `/about/` 收录方式、数据范围、审核与标注、更新频率、纠错入口。

详情页地址使用可读 slug，并由稳定仓库 ID 关联数据；改名时保留旧路径跳转或说明。设计稿不预设最终技术实现。

## 3. 视觉体系

方向：**电影制作工作台**。深炭灰界面与暖白文字为主体，以少量荧光绿强调主要操作、当前状态与关键数字。采用克制的胶片、片场网格视觉，避免大面积霓虹与复杂装饰；正文与数据始终优先。

| 设计令牌 | 建议值 | 用途 |
| --- | --- | --- |
| 页面背景 | `#101112` | 页面底色 |
| 卡片背景 | `#1A1C1D` | 内容容器 |
| 次级背景 | `#242627` | 标签、输入框 |
| 主文字 | `#F2F3EF` | 标题、正文 |
| 次文字 | `#B6BAB4` | 说明与时间 |
| 品牌强调 | `#B5F347` | 主按钮、当前状态和少量强调 |
| 强调色文字 | `#11150A` | 绿色按钮上的文字 |
| 边框 | `#414544` | 输入框、卡片边缘 |
| 状态 | 文字与图标配合 | 不只用颜色表达状态 |

颜色为视觉起点；实际实现时逐项检验对比度，不通过时调整，尤其是小字、禁用状态和绿色标签。

字体：中文优先系统字体，英文和数字使用系统无衬线；桌面主标题 48–56px、页面标题 32px、卡片标题 18–20px、正文 16px、辅助说明不小于 13px。移动主标题 32–36px，正文 15–16px。行高正文 1.6 左右。以上为设计基准，实际以可读性验证。

布局：桌面最大内容宽 1200px，12 列，间距 24px；平板 2 列；手机单列，左右留白 16–20px。断点建议 768px / 1024px。主要点击区域至少 44×44px；键盘焦点清晰，正文及关键操作达到 WCAG AA 对比度，状态不只靠颜色识别。

组件：主按钮荧光绿底深色文字，次按钮深色底浅色描边；标签为浅底圆角胶囊；卡片圆角 12–16px、细边框和轻阴影；图标采用统一线性图标。避免把“免费”“商用”“入门”作为没有证据的营销标签。

## 4. 全局框架

桌面顶栏：左侧星形标记 +「OpenStage」；中间「制作流程」「本周精选」「关于」；右侧搜索图标及搜索入口。当前栏目有文字和下划线状态。移动端顶栏保留品牌、搜索和菜单按钮，菜单展开为全宽列表；搜索有明确关闭按钮。导航不遮盖正文，滚动时的吸顶仅在不压缩可视空间的前提下启用。

页脚：产品一句话、流程/周榜/关于/纠错入口、数据更新时间、AI 内容说明、站点仓库链接。未知更新时间时显示「更新时间暂不可用」。

外链：链接文字说明目标，如「前往 GitHub 查看项目」；新窗口打开时提供可感知提示。移动端固定底部操作仅用于详情页，并保留页面底部空间。

## 5. 页面设计

### 5.1 首页

桌面从上至下：

1. 顶栏。
2. 首屏双栏：左侧眉题「为 AI 短剧创作者准备」，主标题「找到适合你的 AI 创作工具」，说明「按制作流程发现开源项目，先看用途和上手条件，再决定是否尝试。」搜索框占一整行，提示「搜索工具、用途或关键词」；下方为出图、视频、配音、剪辑快捷词。右侧用简洁星图与步骤卡片组成抽象视觉，不展示虚构统计。
3. 「从制作流程开始」：六张步骤卡，显示步骤编号、名称、简短任务说明和项目数量；数量未准备好则不显示。
4. 「本周精选」：附期数、快照时间和「查看完整榜单」，展示最多三张横向项目卡；仅来自已审核榜单。无榜单时显示「第一期榜单正在准备」，链接至分类页。
5. 「最近收录」：三至六个项目，说明为站点收录时间，不暗示项目刚创建。
6. 「编辑推荐」：人工审核的少量条目；只有实际测试过才显示已实测与日期。
7. 页脚。

移动端：首屏变单栏，弱化装饰；六步卡片两列，项目卡单列，列表横向不强制滑动；搜索键盘提交后进入搜索页。首屏可直接看到标题、搜索和流程入口。

### 5.2 流程总览

标题「做 AI 短剧，从这六步开始」，副标题说明工具可组合使用、实际流程不必严格依次。六步以编号卡片呈现：剧本与选题、角色与分镜、出图、出视频、配音与声音、剪辑与后期。每卡包括一句任务描述、典型用途和「查看工具」。桌面 3×2，手机两列或窄屏单列；卡片整体可点击且内部不嵌套链接。底部提供「工作流与自动化」入口。

### 5.3 流程/分类列表

顶部：面包屑「首页 / 制作流程 / 出视频」，步骤编号、名称、解释、数据更新时间。下方「常见任务」快捷筛选，如文生视频、图生视频、口型同步（实际选项来自数据）。

桌面：左侧筛选栏，右侧结果及卡片；手机：筛选按钮打开底部抽屉，包含应用、清除和关闭。筛选项：难度（入门/进阶/专业/未确认）、显卡（无需/可选/需要/未确认）、代码要求、许可证状态。排序提供总星数、最近更新、七日涨星（无数据排后）。筛选条件变更后显示结果数量和已选标签，可逐项删除。筛选、排序、搜索条件写入 URL，便于分享及返回。

项目卡：项目名称与 owner、中文用途一句话、最多三个任务标签、难度/显卡/代码标记、GitHub 星数、可用时的七日净增长、更新时间；仅有人工记录时显示实测。未知值显示「未确认」，绝不显示为「无需」。卡片链接至详情，外链作为独立可聚焦操作。

结果为空：区分「没有符合条件的项目」（提供清除筛选）与「该分类尚未收录」（提供返回流程）。加载失败显示「数据暂时无法加载」及重试，不伪装为空结果。

### 5.4 项目详情

桌面双栏：左侧正文约 2/3，右侧信息卡约 1/3；手机单列，信息卡排在简介后。

- 顶部：面包屑、仓库名、中文用途、分类标签、GitHub 星数和数据更新时间。
- 首要操作：「前往 GitHub 查看项目」，附外链提示。
- 「它能做什么」：一句话与适合人群、已知限制；每段 AI 生成内容标注「AI 辅助整理」，只有经过对应人工核查才加「已人工审核」。
- 「上手条件」：难度、显卡、显存、代码、安装方式、中文支持；每项支持来源链接、核实时间或「未确认」。
- 「如何开始」：1–3 步简述，指向原仓库对应文档，不复制 README 全文。
- 「许可与使用」：代码许可、模型/权重许可和「使用前核对原项目」提示；不得凭单一 SPDX 断言整体可商用。
- 「风险提示」：只有有依据时出现，如声音克隆须获得相关授权。
- 「实测记录」：没有实测时整块隐藏；有则写测试人、时间、环境、实际测试内容和结果限制。
- 数据异常：仓库迁移、归档或不可用时顶部显示状态及核实时间，不提供虚构替代链接。

移动端底部可固定「前往 GitHub」按钮；页面中仍保留可访问的常规链接。

### 5.5 周榜与历史

顶部：标题「本周开源项目观察」，期数、实际快照起止时间、统计范围说明及审核状态。默认只展示审核通过版本。榜单列表按名次显示项目名称、用途、七日净增量、当前星数、难度及详情链接；若可计算则附增长率，基数为零或缺失则不展示。允许少于十条；无足够历史数据时展示「数据积累中」，以独立栏目呈现新项目观察，不标作七日涨星。

下方：编辑点评/视频入口（有内容才显示），历史期数列表，规则链接。单期页保持同模板并固定所用快照及内容版本。首页仅引用最新一期已发布内容。

### 5.6 搜索

顶部搜索框保留关键词，支持回车和清除；展示结果数量、分类与基础筛选。结果卡复用分类列表，匹配词高亮不影响可读性。输入为空时显示热门任务建议；无结果时提供简化关键词、清除筛选和返回流程。加载索引失败要单独提示并提供重试。中文及英文、项目名称和用途均可检索；搜索范围及索引更新时间在界面中说明。

### 5.7 关于

清晰说明：产品目的；GitHub 是数据来源且榜单仅覆盖本站观察池；更新时间和快照缺失处理；收录与人工审核标准；AI 辅助及实测标记含义；代码、模型许可需要分别核对；纠错与收录建议入口；联系与隐私说明。该页不声称 AI 标注本身已满足所有法律要求。正文单列，宽度约 720px，移动端保持舒适行长。

## 6. 交互与异常状态清单

| 场景 | 界面行为 |
| --- | --- |
| 首次访问/无搜索词 | 展示流程和示例关键词 |
| 筛选后无结果 | 解释筛选条件，提供一键清除 |
| 索引或数据加载失败 | 显示失败与重试，不显示零结果 |
| 快照不完整 | 七日增量显示「数据不足」；不进入真实涨星榜 |
| 无已发布周榜 | 展示准备中及分类入口，不泄露草稿 |
| 字段无证据 | 显示「未确认」；不转为否定值 |
| 仓库已归档/不可用 | 显示状态、核实时间和可用的官方地址 |
| 搜索/筛选返回 | 保留 URL 参数和列表位置（可行时） |
| 外链 | 显示目标站及新窗口提示 |
| 窄屏/长标题 | 允许换行，不截断关键状态；不出现横向溢出 |
| 键盘与读屏 | 标题层级、表单标签、焦点、弹窗关闭与状态提示可访问 |

## 7. 验收与待定

视觉验收：桌面 1440px、平板 768px、手机 375px 检查上述全部页面及异常状态；标题、按钮和表单不溢出；键盘可完整操作；文字对比度达标；微信内置浏览器实测。内容验收：所有关键状态和时间有数据依据；AI、人工审核、实测互不混淆；榜单只展示通过审核的数据；所有示例数据在正式上线前替换或标明示意。

待确定：最终品牌标志；细部视觉与字体；视频号和公众号入口；项目提交和纠错渠道；域名与部署；真实数据覆盖和首批项目；榜单审核操作方式。深色方向已确认，设计图为方向示意；字段和布局以本文件与后续评审结果为准。
